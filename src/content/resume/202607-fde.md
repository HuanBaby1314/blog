## 项目经验（问题 → 方案 → 结果）

### autoflow 业务自动化平台（2025 - 至今）

- **问题**：业务场景碎片化（审核/入离职/开店/巡检/对账），每次从零写脚本无法复用，多 agent 协作互相踩坑
- **方案**：自研平台底座——**动作注册**（actions：织信/旺店通/飞书/CDP 域动作）+ **流程编排**（flows：JSON 化多节点链路，ensure_login 等自愈节点复用）+ **RawCDP 通道**（直驱 Edge/ERP 客户端调试协议）+ **审计与通知**（JSONL 留痕 + 飞书绿/橙/红三级卡片）+ **方法树**（决策树索引 30+ 先例，开工先查树、完工必沉淀）
- **结果**：新增一类审批监听从「写一套服务」降为「加一条 WATCHERS 配置」；紧急链路稳定日常运行；多 agent 并行开发有 CHANGELOG 护栏，零互相覆盖事故
- **技术栈**：Python、RawCDP、UIA/pywinauto、飞书 API、PostgreSQL

### 紧急样品审核全链路自动化（2025 - 至今）

- **问题**：电商紧急样品发货卡在 ERP 审核环节——人工跟单小时级，状态机复杂（16/25/30/35/55 多态流转 + 人工驳回暂存），漏审误审都会直接延误发货
- **方案**：调度中心取数 → 建单推送 → 旺店通三级审核（25→35→55）全自动；src_tid 精确反查判单（绕过查询索引分钟级时延的坑）；「指定单号定向审」与「全池链路」两套工具用铁律隔离防连带误审；30 且带驳回原因的人工暂存单红线跳过
- **结果**：紧急审核**分钟级全自动办结**（此前人工小时级）；常态化监控每日窗口自动值守，真实办结才发飞书回执（审批编号 + 申请人 + 原始单号），零误报疲劳
- **技术栈**：Python、调度中心 API、旺店通 API、pg8000、飞书卡片

### 离职办理 / 开店审批监听服务（2026）

- **问题**：HR 异动流程跨三系统（织信/ERP/WMS）+ 飞书审批，人工办理慢且易漏；新店开设要飞书审批→金蝶→ERP 建店→权限多段接力
- **方案**：飞书审批**实时监听框架**（卡片扫描秒级检出 + 5/30 分钟兜底轮询，通用化：新审批类型 = 加一条 regex+flow 配置）；离职三系统账户核验→幂等停用→服务端备注核验；开店按金蝶编码自动推断平台建 ERP 店并开通权限，「**建店失败绝不同意**」守住结果底线；已办理红线保护不再操作
- **结果**：开店首战 **3 单全自动办结**（含权限补办）；离职办理从人工跨系统操作变为「审批通过即办结」；连续失败自动红卡告警，健康检查每 15 分钟防静默挂死
- **技术栈**：Python、MutationObserver、飞书审批 API、旺店通/金蝶 API、Windows 计划任务

### iFDL 金融数据管道 + 巨量云图采集（2024.06 - 至今）

- **问题**：财务每天人工聚合多渠道交易对账，营销数据散在平台后台无导出口
- **方案**：聚合支付宝/招行/建行等多源流水 → 规则审批工作流 → 自动推送银行付款 + 生成金蝶 ERP 凭证（织信低代码受限运行时下工程化，**235 次提交**持续迭代）；巨量云图 Playwright 多账户采集（短信验证码 webhook 自动回填、API 响应拦截、增量回填，完成后飞书告警）
- **结果**：财务对账从人工聚合多平台变为**一条自动管道 + 异常告警**；采集失败/完成状态透明可观测
- **技术栈**：JavaScript(织信平台)、Java/Playwright、PostgreSQL、飞书机器人

### AI 会议预演 RAG + CEO 数字孪生 Agent（2026.03）

- **问题**：管理层会议准备要人工翻知识库文档；希望把高管决策经验沉淀为可交互系统
- **方案**：RAG 全链路（飞书文档抽取 → qwen3-embedding 向量化 → pgvector 检索 → qwen3-8b 生成，**Ollama 本地化保障数据不出企业**）；「感知-认知-执行」三段架构 Agent（LangChain4j，飞书 IM 集成）
- **结果**：会议预演问答可直接检索企业自有知识作答；沉淀出一套可复制到其他业务场景的本地 RAG 模板
- **技术栈**：Spring Boot、LangChain4j、pgvector、Ollama、Qwen3、飞书开放平台

### 旺店通 ERP 桌面 RPA（2026.06）

- **问题**：部分 ERP 操作无 API 可调，只能走 GUI
- **方案**：PyAutoGUI + OpenCV 模板匹配（可选 YOLO 按钮检测）、可视化流程编排（浏览器 UI 编辑工作流）、悬浮控制器单步调试、APScheduler 定时执行、飞书完成通知
- **结果**：无 API 场景也能纳入自动化版图，流程 JSON 化后可交接给非开发同事执行
- **技术栈**：Python、FastAPI、OpenCV、YOLO、pywinauto
